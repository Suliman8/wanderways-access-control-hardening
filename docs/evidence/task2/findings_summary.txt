 [Critical] WW-AUTH-09 - Secret-key disclosure enabling admin session forgery   (VULNERABLE)
 -----------------------------------------------------------------------------------------
   What was done : /api/internal/debug leaked SECRET_KEY='wanderways-dev-secret'. A session cookie for user id 1 was signed with it and accepted: admin stats returned 200 with no password.
   Security impact: Full authentication bypass. With the signing key an attacker forges a valid session for ANY user (including admin) and impersonates them completely. Most severe issue found.
   Evidence      : {"leaked_secret_key": "wanderways-dev-secret", "forged_payload": {"user_id": 1, "role": "admin"}, "admin_stats_status": 200}

 [Critical] WW-PRIV-06 - Privilege escalation to admin via self-service PATCH   (VULNERABLE)
 -----------------------------------------------------------------------------------------
   What was done : ayesha PATCHed her own profile with role=admin; admin stats went from 403 to 200 with no re-authentication.
   Security impact: Complete takeover: any customer promotes themselves to admin in one request and gains every admin capability. The profile endpoint accepts the privileged 'role' field (mass assignment).
   Evidence      : {"stats_before": 403, "role_after_patch": "admin", "stats_after": 200}

 [High] WW-AUTH-08 - Unauthenticated access to all bookings (legacy v1 API)   (VULNERABLE)
 -----------------------------------------------------------------------------------------
   What was done : With no login, GET /api/v1/bookings returned 20 bookings; GET /api/v1/bookings/2 returned Omar Farooq's record.
   Security impact: A completely unauthenticated attacker can exfiltrate every booking and all PII. The retired mobile endpoint was never removed and has no auth.
   Evidence      : {"count": 20, "single_status": 200, "status_code": 200}

 [High] WW-BAC-04 - Delete any booking as a non-admin (broken RBAC)   (VULNERABLE)
 -----------------------------------------------------------------------------------------
   What was done : ayesha (customer) sent DELETE /api/bookings/14 -> 200; the record is now gone (re-read returns 404).
   Security impact: A low-privilege user can permanently destroy any booking. Destructive admin action with no role check and no recovery.
   Evidence      : {"delete_status": 200, "reread_status": 404}

 [High] WW-BAC-07 - Admin user directory exposed to non-admins (broken RBAC)   (VULNERABLE)
 -----------------------------------------------------------------------------------------
   What was done : ayesha (customer) read /api/admin/users -> 200 listing 7 accounts, while /api/admin/stats correctly returned 403.
   Security impact: The full staff/customer directory (usernames, emails, phones, roles) leaks to any logged-in user. Inconsistent checks show the role guard was forgotten on this route.
   Evidence      : {"accounts_listed": 7, "users_status": 200, "stats_status": 403}

 [High] WW-BAC-10 - Authorisation from a client-editable cookie (CSV export)   (VULNERABLE)
 -----------------------------------------------------------------------------------------
   What was done : With ww_role=customer the export returned 403; after editing the cookie to ww_role=admin it returned 200 - a CSV of 20 bookings with passports and cards.
   Security impact: Authorisation is decided by an unsigned cookie the client fully controls, so anyone downloads the full booking database (names, emails, passports, card last-4) by editing one cookie value.
   Evidence      : {"blocked_status": 403, "bypassed_status": 200, "csv_rows": 20, "saved": "docs/evidence/task2/leaked_bookings_export.csv"}

 [High] WW-IDOR-01 - Read any user's booking (horizontal IDOR)   (VULNERABLE)

 [High] WW-IDOR-02 - Modify / re-price / steal any booking (IDOR + mass assignment)   (VULNERABLE)
